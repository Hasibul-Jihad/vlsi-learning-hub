Quick Start — What is VLSI?
What you'll study
VLSI — Very Large Scale Integration
VLSI is the process of creating integrated circuits by combining millions of transistors into a single chip. As a Level 4 BSc student, you'll learn to design and simulate digital circuits using HDLs (Hardware Description Languages) like Verilog and VHDL, then synthesize them onto FPGAs.

Verilog Fundamentals
Module Structure — The Building Block of Every Verilog Design
Every Verilog design is made of modules. Think of a module like a function in programming — it has inputs, outputs, and internal logic. Here's the standard structure:
// Module: AND gate example module and_gate ( input wire a, // Input port a input wire b, // Input port b output wire y // Output port y ); // Dataflow (continuous assignment) assign y = a & b; // AND logic endmodule
wire — for combinational reg — for procedural blocks assign — continuous
Behavioral Modeling — Always Blocks
// D Flip-flop with synchronous reset module d_ff ( input wire clk, rst, d, output reg q ); // Sequential: triggered on clock edge always @(posedge clk) begin if (rst) q <= 1'b0; // Non-blocking assignment! else q <= d; end endmodule
Critical rule

Always use <= (non-blocking) inside always @(posedge clk) blocks. Use = (blocking) only in combinational always @(*) blocks. Mixing them causes simulation vs synthesis mismatches.

4-bit Ripple Carry Adder — Structural Modeling
// Full adder module module full_adder ( input a, b, cin, output sum, cout ); assign sum = a ^ b ^ cin; assign cout = (a & b) | (b & cin) | (a & cin); endmodule // 4-bit Ripple Carry Adder — instantiates 4 full adders module rca_4bit ( input [3:0] a, b, input cin, output [3:0] sum, output cout ); wire [2:0] carry; // Internal carry signals full_adder fa0 (.a(a[0]),.b(b[0]),.cin(cin), .sum(sum[0]),.cout(carry[0])); full_adder fa1 (.a(a[1]),.b(b[1]),.cin(carry[0]),.sum(sum[1]),.cout(carry[1])); full_adder fa2 (.a(a[2]),.b(b[2]),.cin(carry[1]),.sum(sum[2]),.cout(carry[2])); full_adder fa3 (.a(a[3]),.b(b[3]),.cin(carry[2]),.sum(sum[3]),.cout(cout)); endmodule
Testbench Template
Every design needs a testbench. Here's the standard template — copy and adapt for any module you write:
// Testbench for rca_4bit module tb_rca; // No ports in testbench! // Declare signals (use reg for driven, wire for outputs) reg [3:0] a, b; reg cin; wire [3:0] sum; wire cout; // Instantiate Device Under Test (DUT) rca_4bit dut (.a(a),.b(b),.cin(cin),.sum(sum),.cout(cout)); initial begin $dumpfile("tb.vcd"); $dumpvars(0, tb_rca); // GTKWave dump // Test vectors a=4'd3; b=4'd5; cin=0; #10; $display("3+5=%0d cout=%b", sum, cout); a=4'd15; b=4'd1; cin=0; #10; $display("15+1=%0d cout=%b", sum, cout); $finish; end endmodule
Common Pitfalls — Don't Make These Mistakes
Latch inferenceIf an always @(*) block doesn't assign an output in every branch of an if/case, the synthesiser infers a latch. Always use default in case statements and cover all conditions.
Blocking in sequentialUsing = instead of <= in clocked always blocks causes race conditions in simulation and incorrect synthesis. Use <= always in sequential blocks.
Sensitivity listIn Verilog-2001, use always @(*) for combinational — never manually list signals. One missing signal causes simulation vs synthesis mismatch.
Integer divisionVerilog integers truncate. 5/2 = 2, not 2.5. Use explicit widths and be careful with signed arithmetic.
Multiple driversNever drive a wire from two assign statements — causes X (unknown) in simulation. Use mux logic instead.

FPGA Architecture
What is an FPGA?
Field-Programmable Gate Array — Reconfigurable Hardware
An FPGA is a chip containing thousands of configurable logic blocks (CLBs), flip-flops, and programmable interconnects. You program it with a bitstream generated from your Verilog/VHDL design. Unlike an ASIC (fixed forever), an FPGA can be reprogrammed as many times as needed — perfect for prototyping.
LUT (Look-Up Table) CLB (Configurable Logic Block) IOB (I/O Block) DSP48 (Math blocks) BRAM (Block RAM)

Key HDL Concepts for BSc Level 4
Concept 1 — Fundamental
Synthesis vs Simulation
Simulation runs your Verilog on a computer to check behaviour. Synthesis converts Verilog to actual logic gates (netlist) that can be placed on an FPGA or ASIC. Not all Verilog is synthesisable — $display, #delays, and initial blocks are simulation-only constructs.
Simulation only$display, $monitor, #delay, $finish, initial begin
Synthesisablealways @(posedge clk), assign, if/else, case, modules
RuleNever put simulation-only constructs in your design files. Only put them in testbenches.
Concept 2 — Critical
Finite State Machines (FSM)
FSMs are the core of sequential digital design. Every controller, protocol handler, and interface is an FSM. There are two types — learn both.
Mealy FSMOutput depends on current state AND inputs. Faster response (output changes immediately with input). More complex.
Moore FSMOutput depends only on current state. Simpler, safer, preferred in FPGA design.
3-block FSM styleBlock 1: state register (sequential). Block 2: next-state logic (combinational). Block 3: output logic (combinational). This is the industry-standard coding style.
// Moore FSM — 3-block style module traffic_light ( input clk, rst, output reg [1:0] light // 00=RED 01=GREEN 10=YELLOW ); // State encoding parameter RED=2'd0, GREEN=2'd1, YELLOW=2'd2; reg [1:0] state, next; // Block 1: State register always @(posedge clk) begin if (rst) state <= RED; else state <= next; end // Block 2: Next-state logic always @(*) begin case (state) RED: next = GREEN; GREEN: next = YELLOW; YELLOW: next = RED; default: next = RED; endcase end // Block 3: Output logic (Moore — only depends on state) always @(*) light = state; endmodule
Concept 3 — Timing
Setup Time, Hold Time & Critical Path
The most common cause of FPGA timing failures at BSc level.
Setup timeData must be stable BEFORE the clock edge for at least t_su. Violating this means data might not be latched correctly. Caused by logic being too slow (long critical path).
Hold timeData must stay stable AFTER the clock edge for at least t_h. Violating this corrupts the flip-flop. Caused by clock skew or very fast combinational paths.
Critical pathThe longest combinational path between two flip-flops. It determines your maximum clock frequency: f_max = 1 / (critical_path + t_su + t_clk_to_q)
Fix setup violationInsert pipeline registers to break long paths. Reduce logic depth. Use faster carry chains (e.g. DSP48 blocks for arithmetic).
View in VivadoReports → Timing → Check Timing. The critical path is highlighted. WNS (Worst Negative Slack) should be > 0.
Concept 4 — Advanced
Clock Domain Crossing (CDC)
When signals cross between different clock domains, metastability can occur — the flip-flop output becomes unpredictable. Always synchronise signals crossing clock domains using a 2-flop synchroniser (for single-bit signals) or a FIFO (for multi-bit data).
Golden rule

Never directly connect a signal from one clock domain to logic in another clock domain without a synchroniser. This is the #1 cause of intermittent failures in digital designs that "pass simulation but fail on hardware."

Your VLSI learning path — Level 4 BSc

This roadmap goes from absolute beginner to thesis-ready VLSI student in one academic year. Each phase builds on the last — don't skip phases.

Phase-by-Phase Roadmap
Phase 1 — Months 1–2 · Foundations
Digital logic from scratch
Before touching HDL, you must understand the concepts it describes. This phase is all about digital logic theory.
Boolean algebraAND, OR, NOT, NAND, NOR, XOR. Truth tables. DeMorgan's theorem. Karnaugh maps for simplification.
Combinational circuitsMultiplexers, decoders, encoders, adders (half, full, ripple carry, carry lookahead).
Sequential circuitsSR latch, D latch, D flip-flop, JK flip-flop. Registers. Counters. Difference between latch and flip-flop.
ResourceNeso Academy Digital Electronics playlist + Harris & Harris Ch. 1–4
CheckpointCan design a 4-bit counter and a 2-bit multiplier from logic gates on paper.
Phase 2 — Months 2–3 · HDL Basics
Learn Verilog — write real code
Move from paper circuits to code. Simulate before synthesising. HDLBits is your primary resource this phase.
Week 1Verilog syntax: module, port, wire, reg, assign. Do HDLBits "Getting Started" and "Wires" section entirely.
Week 2Vectors, multi-bit operations, part-select. HDLBits "Vectors" section. Write a 4-bit adder.
Week 3Always blocks, if/case, behavioral modeling. HDLBits "Procedures" section. Write a D flip-flop and a mux.
Week 4FSMs. Implement a traffic light controller. HDLBits "Finite State Machines" section.
ToolEDAplayground (no install) or Icarus + GTKWave locally
CheckpointCan write and simulate a working FSM with testbench in under 2 hours.
Phase 3 — Months 3–4 · FPGA Implementation
Get onto hardware — use real tools
Install toolsXilinx Vivado WebPACK or Intel Quartus Lite. Set up an FPGA board or use EDAplayground.
First projectLED blinker → 7-segment display → simple FSM on real hardware.
Learn XDC/SDCWrite constraints files: clock period, I/O timing, pin assignments.
Timing analysisRead Vivado timing reports. Understand WNS (worst negative slack). Fix one timing violation.
CheckpointWorking UART or VGA controller synthesised and running on an FPGA board.
Phase 4 — Months 4–6 · System Design
Build complex systems — thesis-level projects
RTL designDesign a complete ALU (arithmetic logic unit) with all operations. Pipelined datapath.
Memory systemsImplement FIFO, BRAM interfaces, SPI/I2C controllers.
VerificationConstrained-random testbenches. Coverage-driven verification basics. SystemVerilog assertions.
Soft processorImplement a simple 8-bit or 16-bit CPU from scratch in Verilog — the ultimate VLSI project.
CheckpointA working pipelined processor or complex system running on FPGA, with full testbench verification.

Fixed Practice Questions
Q1. What is the difference between wire and reg in Verilog?
✓ Correct. Despite the name, reg doesn't always become a register in hardware — a reg in an always @(*) block becomes combinational logic. The name just means it can be assigned in a procedural block.
Q2. Which assignment operator should you use inside a clocked always @(posedge clk) block?
✓ Correct. Non-blocking assignments all evaluate the right-hand sides simultaneously, then update — this correctly models flip-flop behaviour where all outputs update at the same clock edge.
Q3. What does "setup time violation" mean in FPGA timing analysis?
✓ Correct. Setup violation (negative WNS) means your critical path is too long. Fix: reduce logic depth, add pipeline registers, or lower your clock frequency.
Q4. In a Moore FSM, what does the output depend on?
✓ Correct. Moore: output = f(state). Mealy: output = f(state, inputs). Moore outputs are glitch-free and synchronised to the clock; Mealy outputs respond immediately to input changes.

VLSI Glossary — Essential Terms
ALU
Arithmetic Logic Unit — performs arithmetic (+, −) and logic (AND, OR, XOR) operations. The computation core of a CPU datapath.
ASIC
Application-Specific Integrated Circuit — a chip designed for one specific purpose, manufactured permanently. High performance, high NRE cost. Cannot be reprogrammed.
Bitstream
The binary file produced after place-and-route that programs the FPGA's configuration memory. Loaded via USB or JTAG.
CLB
Configurable Logic Block — the basic unit of an FPGA. Contains LUTs, flip-flops, carry chains, and multiplexers.
Clock skew
The difference in clock arrival time between two flip-flops in the same clock domain. Causes hold-time violations when negative (clock arrives early at receiver).
Critical path
The combinational path with the longest delay between two sequential elements. Determines maximum clock frequency: f_max = 1 / t_critical_path.
DFF
D Flip-Flop — the fundamental storage element in digital design. Samples input D on the rising clock edge and holds it at output Q until the next clock edge.
FPGA
Field-Programmable Gate Array — reconfigurable chip containing LUTs, flip-flops, DSP blocks, and BRAMs. Programmed using bitstream. Can be reprogrammed unlimited times.
FSM
Finite State Machine — a circuit with a finite number of states, transitions, and outputs. Two types: Moore (output = f(state)) and Mealy (output = f(state, input)).
HDL
Hardware Description Language — a programming language used to describe digital hardware. Main examples: Verilog, VHDL, SystemVerilog.
Hold time
Minimum time data must remain stable AFTER the clock edge for reliable sampling. Hold violations are caused by paths that are too fast (clock skew or minimal logic).
LUT
Look-Up Table — implements any N-input boolean function using a truth table stored in SRAM. A 6-input LUT (LUT6) is the basic logic primitive in most modern FPGAs.
Metastability
An unstable state where a flip-flop output is neither 0 nor 1. Occurs when setup or hold time is violated. Resolved using synchroniser chains for clock domain crossing.
Netlist
The output of synthesis — a circuit described as interconnected gates and flip-flops. The bridge between HDL code and physical layout.
Pipeline
Breaking a combinational path into stages separated by flip-flops. Increases throughput (can start new computation every cycle) but adds latency (takes more cycles to complete one computation).
RTL
Register-Transfer Level — the abstraction level at which HDL is written. Describes how data moves between registers and what operations are performed. The level at which synthesis operates.
Setup time
Minimum time data must be stable BEFORE the clock edge for reliable sampling. Setup violations (negative WNS) mean the critical path is too long for the target clock frequency.
Testbench
A Verilog module with no ports that instantiates your design, applies inputs, and checks outputs. Used for functional verification. Contains simulation-only constructs like $display and #delay.
VHDL
VHSIC Hardware Description Language — the other major HDL. More verbose than Verilog, strongly typed. Common in aerospace and defence. Preferred in Europe; Verilog preferred in US/Asia.
WNS
Worst Negative Slack — the timing margin of the most critical path. WNS > 0 means timing is met. WNS < 0 means timing failure — your design will not work reliably at the target frequency.

About this project

A real-time digital audio equaliser on FPGA — the ideal BSc Level 4 VLSI project. You receive audio samples over I2S, apply FIR filters (bass/mid/treble) in hardware, and output processed audio. Covers FSMs, fixed-point arithmetic, pipelining, clock domains, and I/O interfaces — all in synthesisable Verilog.

Phase 1 goal
Pass audio through the FPGA untouched: microphone → I2S RX → FIFO → I2S TX → speaker. If you hear the input clearly through the output, your clocking, I2S timing, and CDC are all correct. Build everything else on top of a working loopback.
Phase 2 goal
Insert a single low-pass FIR filter in the signal path. Verify with simulation first — feed in a sine wave testbench, check the output spectrum. Then run on hardware. You should hear the treble frequencies cut.
Phase 3 goal
Run three FIR filters in parallel (bass, mid, treble), each with different coefficients. Sum the three outputs with independent gain multipliers. You now have a 3-band equaliser.
Phase 4 goal
Use the Basys 3 slide switches to control bass/mid/treble gain in real time. 3 switches per band = 8 gain levels each. Add 7-segment display showing active EQ preset. This is your demo.
Verilog Source Code — All Modules
Module 1 — i2s_rx.v
I2S Receiver — deserialise serial audio into 24-bit parallel samples
I2S uses 3 wires: BCLK (bit clock ~3 MHz), LRCLK (left/right at 48 kHz), and SDATA (serial data, MSB first). This module synchronises all three into the 100 MHz system clock domain, detects edges, and shifts bits into a 24-bit register. When LRCLK toggles, the completed sample is latched.
Key concept: The 2-flop synchroniser on every input prevents metastability when crossing from the audio clock domain to the system clock domain. Never omit these — intermittent failures on hardware are almost always a missing synchroniser.
// ───────────────────────────────────────────────────────────── // Module : i2s_rx // Purpose : Deserialise I2S audio stream → 24-bit parallel samples // Protocol: Standard I2S — MSB first, data valid on BCLK rising edge, // one BCLK after LRCLK transition (Philips I2S spec) // Clocks : clk = 100 MHz system; bclk/lrclk from audio domain // ───────────────────────────────────────────────────────────── module i2s_rx ( input wire clk, // 100 MHz system clock input wire rst_n, // Active-low synchronous reset input wire bclk, // I2S bit clock ~3.072 MHz input wire lrclk, // Left/Right select, 48 kHz input wire sdata, // Serial audio data (MSB first) output reg [23:0] left_sample, // Left channel, valid when sample_valid=1 output reg [23:0] right_sample, // Right channel output reg sample_valid // 1-cycle pulse: new stereo frame ready ); // ── 2-flop synchronisers (clock domain crossing) ───────── // Audio signals come from MCLK domain. Capture→stabilise. reg bclk_r1, bclk_r2; reg lrclk_r1, lrclk_r2; reg sdata_r1, sdata_r2; always @(posedge clk) begin if (!rst_n) begin {bclk_r1,bclk_r2,lrclk_r1,lrclk_r2,sdata_r1,sdata_r2} <= 6'd0; end else begin bclk_r1 <= bclk; bclk_r2 <= bclk_r1; lrclk_r1 <= lrclk; lrclk_r2 <= lrclk_r1; sdata_r1 <= sdata; sdata_r2 <= sdata_r1; end end // ── Edge detection (previous-value comparison) ─────────── reg bclk_prev, lrclk_prev; wire bclk_rise = bclk_r2 & ~bclk_prev; wire lrclk_rise = lrclk_r2 & ~lrclk_prev; wire lrclk_fall = ~lrclk_r2 & lrclk_prev; always @(posedge clk) {bclk_prev, lrclk_prev} <= {bclk_r2, lrclk_r2}; // ── Shift register and channel tracking ────────────────── reg [23:0] shift_reg; // Accumulates bits MSB-first reg [4:0] bit_cnt; // 0..23 reg channel; // 0=LEFT 1=RIGHT always @(posedge clk) begin if (!rst_n) begin shift_reg <= 0; bit_cnt <= 0; channel <= 0; left_sample <= 0; right_sample <= 0; sample_valid <= 0; end else begin sample_valid <= 1'b0; // default: pulse de-asserted if (lrclk_rise || lrclk_fall) begin // LRCLK edge = end of one channel's 24 bits if (channel == 1'b0) left_sample <= shift_reg; else begin right_sample <= shift_reg; sample_valid <= 1'b1; // Both channels latched → valid frame end channel <= ~channel; bit_cnt <= 5'd0; shift_reg <= 24'd0; end else if (bclk_rise && bit_cnt < 5'd24) begin // BCLK rising edge: shift in next bit (MSB first) shift_reg <= {shift_reg[22:0], sdata_r2}; bit_cnt <= bit_cnt + 5'd1; end end end endmodule
Module 2 — fir_filter.v
FIR Filter — direct-form implementation with fixed-point arithmetic
A Finite Impulse Response filter computes y[n] = Σ h[k] · x[n−k]. In hardware this is a delay line (shift register of past samples), N multipliers (sample × coefficient), and an adder tree. Coefficients are pre-computed in Python (see the Coefficients tab) and stored as constants. Uses Q1.15 fixed-point: 1 sign bit + 15 fractional bits.
Why fixed-point? FPGAs have no native floating-point hardware. Fixed-point arithmetic uses integer multipliers (DSP48 blocks) which are fast, small, and synthesisable. Q1.15 gives you a range of −1.0 to +0.99997 with 0.00003 resolution — more than enough for audio filter coefficients.
// ───────────────────────────────────────────────────────────── // Module : fir_filter // Purpose : N-tap FIR filter, direct-form, fixed-point Q1.15 // Format : Input/output = signed 24-bit audio sample // Coefficients = signed 16-bit Q1.15 (range −1.0 to +1.0) // Latency : N+1 clock cycles (pipeline delay — constant, not a problem) // ───────────────────────────────────────────────────────────── module fir_filter #( parameter N_TAPS = 32 // Number of filter taps (order = N-1) ) ( input wire clk, input wire rst_n, input wire sample_valid, // 1-cycle pulse: new sample on data_in input wire signed [23:0] data_in, output reg signed [23:0] data_out, output reg out_valid // Pulses when data_out is valid ); // ── Coefficient ROM (set from parameter or localparams below) ─ // Replace these 32 values with your computed coefficients. // These are a generic low-pass example (cutoff ~4 kHz @ 48kHz SR) localparam signed [15:0] COEFF [0:31] = '{ 16'sh0012, 16'sh0028, 16'sh0057, 16'sh009F, 16'sh0101, 16'sh0177, 16'sh01F9, 16'sh027A, 16'sh02ED, 16'sh0342, 16'sh036E, 16'sh0368, 16'sh0328, 16'sh02A9, 16'sh01FB, 16'sh0130, 16'sh0130, 16'sh01FB, 16'sh02A9, 16'sh0328, 16'sh0368, 16'sh036E, 16'sh0342, 16'sh02ED, 16'sh027A, 16'sh01F9, 16'sh0177, 16'sh0101, 16'sh009F, 16'sh0057, 16'sh0028, 16'sh0012 }; // ── Delay line (shift register of past N samples) ───────── reg signed [23:0] delay_line [0:N_TAPS-1]; integer i; always @(posedge clk) begin if (!rst_n) begin for (i=0; i<N_TAPS; i=i+1) delay_line[i] <= 24'd0; end else if (sample_valid) begin // Shift all samples one position older for (i=N_TAPS-1; i>0; i=i-1) delay_line[i] <= delay_line[i-1]; delay_line[0] <= data_in; // Newest sample at index 0 end end // ── Multiply-Accumulate (MAC) ───────────────────────────── // Each sample × its coefficient = 24-bit × 16-bit = 40-bit product // Accumulate N products → sum is 40+log2(N) bits wide reg signed [47:0] acc; // Accumulator (wide enough to prevent overflow) reg [1:0] valid_delay; // Pipeline delay to track output valid always @(posedge clk) begin if (!rst_n) begin acc <= 48'd0; data_out <= 24'd0; out_valid <= 0; valid_delay <= 0; end else begin valid_delay <= {valid_delay[0], sample_valid}; out_valid <= valid_delay[1]; if (sample_valid) begin acc <= 48'sd0; for (i=0; i<N_TAPS; i=i+1) // Signed multiply: extend both operands then multiply acc <= acc + ({{8{delay_line[i][23]}}, delay_line[i]} * {{32{COEFF[i][15]}}, COEFF[i]}); end // Truncate back to 24 bits: drop sign extension + fractional bits // Q1.15 × Q8.16 → result is in bits [38:15] of the accumulator if (valid_delay[0]) data_out <= acc[38:15]; end end endmodule
Module 3 — eq_filter_bank.v
3-Band Filter Bank — instantiates 3 parallel FIR filters
This module instantiates three copies of the FIR filter module, each with different coefficients for bass (low-pass), mid (band-pass), and treble (high-pass). All three receive the same input sample simultaneously and produce independent filtered outputs.
// ───────────────────────────────────────────────────────────── // Module : eq_filter_bank // Purpose : 3-band equaliser — bass / mid / treble in parallel // Each band uses a separate FIR with different coefficients loaded // via the COEFF_FILE parameter (or hardcoded localparam arrays) // ───────────────────────────────────────────────────────────── module eq_filter_bank ( input wire clk, input wire rst_n, input wire sample_valid, input wire signed [23:0] audio_in, output wire signed [23:0] bass_out, output wire signed [23:0] mid_out, output wire signed [23:0] treble_out, output wire out_valid // All three share the same latency ); // Bass band: low-pass FIR, cutoff ~300 Hz fir_filter #(.N_TAPS(32)) bass_fir ( .clk(clk), .rst_n(rst_n), .sample_valid(sample_valid), .data_in(audio_in), .data_out(bass_out), .out_valid(out_valid) // Only need one — they're all identical ); // Mid band: band-pass FIR, passband 300 Hz – 3 kHz // Note: use different COEFF values inside fir_filter for mid/treble // Easiest: create fir_filter_mid.v and fir_filter_treble.v with // different hardcoded localparam COEFF arrays fir_filter #(.N_TAPS(32)) mid_fir ( .clk(clk), .rst_n(rst_n), .sample_valid(sample_valid), .data_in(audio_in), .data_out(mid_out), .out_valid() // Unused — tied to bass_fir ); // Treble band: high-pass FIR, cutoff ~3 kHz fir_filter #(.N_TAPS(32)) treble_fir ( .clk(clk), .rst_n(rst_n), .sample_valid(sample_valid), .data_in(audio_in), .data_out(treble_out), .out_valid() ); endmodule
Module 4 — gain_mixer.v
Gain Stage & Mixer — multiply each band by a gain factor, sum outputs
Takes the three band outputs and multiplies each by a user-controlled gain value (from switches), then sums them. Uses the same Q1.15 fixed-point arithmetic as the filter. The gain values come from the 3 slide switches on the Basys 3 — 3 switches per band gives 8 gain levels (0% to 200%).
// ───────────────────────────────────────────────────────────── // Module : gain_mixer // Purpose : Scale each EQ band by gain, sum to one stereo output // Gain : 3-bit input per band → 8 levels (0.0 to 2.0 step 0.286) // ───────────────────────────────────────────────────────────── module gain_mixer ( input wire clk, input wire rst_n, input wire in_valid, input wire signed [23:0] bass_in, input wire signed [23:0] mid_in, input wire signed [23:0] treble_in, input wire [2:0] bass_gain, // From slide switches SW[2:0] input wire [2:0] mid_gain, // From SW[5:3] input wire [2:0] treble_gain, // From SW[8:6] output reg signed [23:0] audio_out, output reg out_valid ); // Gain LUT: 3-bit → Q1.15 fixed-point multiplier // 0=mute, 1=25%, 2=50%, 3=75%, 4=100%, 5=125%, 6=150%, 7=200% function signed [15:0] gain_lut; input [2:0] sel; case (sel) 3'd0: gain_lut = 16'sh0000; // 0.00 — mute 3'd1: gain_lut = 16'sh2000; // 0.25 3'd2: gain_lut = 16'sh4000; // 0.50 3'd3: gain_lut = 16'sh6000; // 0.75 3'd4: gain_lut = 16'sh7FFF; // 1.00 — unity gain 3'd5: gain_lut = 16'shA000; // 1.25 3'd6: gain_lut = 16'shC000; // 1.50 3'd7: gain_lut = 16'shFFFF; // 2.00 — max boost endcase endfunction reg signed [47:0] bass_scaled, mid_scaled, treble_scaled; reg signed [47:0] mix_sum; always @(posedge clk) begin if (!rst_n) begin audio_out <= 24'd0; out_valid <= 0; end else begin out_valid <= in_valid; if (in_valid) begin // Multiply each band by its Q1.15 gain factor bass_scaled <= $signed(bass_in) * $signed(gain_lut(bass_gain)); mid_scaled <= $signed(mid_in) * $signed(gain_lut(mid_gain)); treble_scaled <= $signed(treble_in) * $signed(gain_lut(treble_gain)); // Sum all three bands mix_sum <= bass_scaled + mid_scaled + treble_scaled; // Truncate to 24-bit audio (bits [38:15] after Q1.15 multiply) audio_out <= mix_sum[38:15]; end end end endmodule
Module 5 — i2s_tx.v
I2S Transmitter — serialise 24-bit samples back to I2S output
The mirror of i2s_rx. Loads the processed 24-bit sample into a shift register and clocks it out MSB-first on SDATA, one bit per BCLK cycle, with LRCLK indicating left or right channel.
// ───────────────────────────────────────────────────────────── // Module : i2s_tx // Purpose : Serialise 24-bit parallel samples → I2S output stream // Note : bclk and lrclk are OUTPUTS here (TX generates the clocks) // OR pass them from RX module for synchronous loopback // ───────────────────────────────────────────────────────────── module i2s_tx ( input wire clk, input wire rst_n, input wire bclk, // Shared with RX (same codec) input wire lrclk, input wire signed [23:0] left_in, input wire signed [23:0] right_in, input wire load, // Pulse: latch new sample into shift reg output reg sdata // Serial output to codec ); reg bclk_r1, bclk_r2, bclk_prev; reg lrclk_r1, lrclk_r2, lrclk_prev; wire bclk_fall = ~bclk_r2 & bclk_prev; // Drive SDATA on FALLING edge wire lrclk_rise = lrclk_r2 & ~lrclk_prev; wire lrclk_fall = ~lrclk_r2 & lrclk_prev; always @(posedge clk) begin bclk_r1 <= bclk; bclk_r2 <= bclk_r1; bclk_prev <= bclk_r2; lrclk_r1 <= lrclk; lrclk_r2 <= lrclk_r1; lrclk_prev <= lrclk_r2; end reg [23:0] shift_reg; reg [4:0] bit_cnt; reg channel; always @(posedge clk) begin if (!rst_n) begin sdata <= 0; shift_reg <= 0; bit_cnt <= 0; channel <= 0; end else begin if (lrclk_rise || lrclk_fall) begin // Load next channel's sample into shift register shift_reg <= (lrclk_rise) ? left_in : right_in; bit_cnt <= 5'd0; channel <= ~channel; end else if (bclk_fall) begin // Output MSB first on falling edge of BCLK sdata <= shift_reg[23]; shift_reg <= {shift_reg[22:0], 1'b0}; bit_cnt <= bit_cnt + 1; end end end endmodule
Top Level — audio_eq_top.v
Top-level module — wires all modules together and connects to FPGA pins
This is the module you constrain in your XDC file and synthesise. It instantiates all 5 sub-modules, connects the signals between them, and maps ports to physical FPGA pins (switches, LEDs, Pmod connectors).
// ───────────────────────────────────────────────────────────── // Module : audio_eq_top // Purpose : Top-level: wire all sub-modules, connect to FPGA pins // Board : Basys 3 (Artix-7) + Digilent Pmod I2S2 // ───────────────────────────────────────────────────────────── module audio_eq_top ( input wire clk_100mhz, // Basys 3 onboard 100 MHz oscillator input wire btnC, // Centre button = reset input wire [8:0] sw, // SW[2:0]=bass SW[5:3]=mid SW[8:6]=treble // Pmod I2S2 connector (JA port on Basys 3) input wire i2s_bclk, input wire i2s_lrclk, input wire i2s_sdata_in, // From ADC (microphone) output wire i2s_sdata_out, // To DAC (speaker/headphone) output wire i2s_mclk, // Master clock to codec (12.288 MHz) output wire [3:0] led // Activity LEDs ); wire rst_n = ~btnC; // ── Generate 12.288 MHz MCLK from 100 MHz using MMCM ────── // In Vivado: use Clocking Wizard IP, set output to 12.288 MHz // For simulation / quick test: use a simple clock divider clk_wiz_0 mclk_gen ( .clk_in1(clk_100mhz), .clk_out1(i2s_mclk), .locked() ); // ── Internal wires ───────────────────────────────────────── wire signed [23:0] left_rx, right_rx; wire rx_valid; wire signed [23:0] bass_l, mid_l, treble_l; wire signed [23:0] bass_r, mid_r, treble_r; wire fir_valid; wire signed [23:0] mixed_l, mixed_r; wire mix_valid; // ── I2S Receiver ─────────────────────────────────────────── i2s_rx rx ( .clk(clk_100mhz), .rst_n(rst_n), .bclk(i2s_bclk), .lrclk(i2s_lrclk), .sdata(i2s_sdata_in), .left_sample(left_rx), .right_sample(right_rx), .sample_valid(rx_valid) ); // ── FIR Filter Bank — LEFT channel ───────────────────────── eq_filter_bank fir_left ( .clk(clk_100mhz), .rst_n(rst_n), .sample_valid(rx_valid), .audio_in(left_rx), .bass_out(bass_l), .mid_out(mid_l), .treble_out(treble_l), .out_valid(fir_valid) ); // ── FIR Filter Bank — RIGHT channel ──────────────────────── eq_filter_bank fir_right ( .clk(clk_100mhz), .rst_n(rst_n), .sample_valid(rx_valid), .audio_in(right_rx), .bass_out(bass_r), .mid_out(mid_r), .treble_out(treble_r), .out_valid() ); System testbench — feed a sine wave in, verify filtered output
This testbench generates a synthetic I2S stream containing a 1 kHz sine wave, drives it into the full system, and dumps the waveform to a VCD file for inspection in GTKWave. Verify that the output spectrum changes as expected when you toggle the filter band.
// Testbench: drives synthetic I2S with 1kHz sine, verifies output module tb_audio_eq; reg clk_100mhz, rst_n; reg bclk, lrclk, sdata_in; wire sdata_out; // Instantiate DUT (skip MCLK gen for simulation) i2s_rx dut_rx ( .clk(clk_100mhz), .rst_n(rst_n), .bclk(bclk), .lrclk(lrclk), .sdata(sdata_in), .left_sample(), .right_sample(), .sample_valid() ); // 100 MHz system clock initial clk_100mhz = 0; always #5 clk_100mhz = ~clk_100mhz; // 10 ns period // 3.072 MHz BCLK (for 48kHz × 64 bits per frame) initial bclk = 0; always #163 bclk = ~bclk; // ~163 ns half-period // 48 kHz LRCLK (toggles every 32 BCLKs) integer bclk_count = 0; always @(posedge bclk) begin bclk_count <= bclk_count + 1; if (bclk_count == 31) begin lrclk <= ~lrclk; bclk_count <= 0; end end // Sine wave lookup: 1 kHz at 48 kHz sample rate = 48 samples/cycle integer sample_idx = 0; reg [23:0] sine_sample; integer bit_idx; always @(negedge lrclk) begin // New sample every LRCLK sine_sample = $rtoi(8388607.0 * $sin(2.0 * 3.14159 * sample_idx / 48.0)); sample_idx = (sample_idx + 1) % 48; end always @(negedge bclk) begin // Drive SDATA MSB first on BCLK falling sdata_in = sine_sample[23 - bit_idx]; bit_idx = (bit_idx + 1) % 24; end initial begin $dumpfile("audio_eq.vcd"); $dumpvars(0, tb_audio_eq); rst_n = 0; lrclk = 0; sdata_in = 0; bit_idx = 0; #500 rst_n = 1; #5_000_000; // Simulate 5 ms of audio $display("Simulation complete."); $finish; end endmodule
Run this testbench

With Icarus Verilog: iverilog -o sim tb_audio_eq.v i2s_rx.v fir_filter.v && vvp sim
Then open the waveform: gtkwave audio_eq.vcd
In GTKWave, add the signals sample_valid, left_sample, data_out to verify the filter is working.

Filter Coefficients — Python script
Generate FIR coefficients in Python, convert to Q1.15 hex for Verilog
Use SciPy to design the filters, then convert the floating-point coefficients to Q1.15 fixed-point integers. Copy the output directly into the COEFF array in your fir_filter.v files. Run this once per band.
# Run this in Python to generate all 3 bands' Verilog coefficients # pip install scipy numpy import numpy as np from scipy.signal import firwin, freqz FS = 48000 # Sample rate (Hz) N_TAPS = 32 # Must match N_TAPS in Verilog module Q_SCALE = 2**15 # Q1.15: multiply float coefficient by 32768 def to_q15_hex(coeffs): """Convert float coefficients to Q1.15 signed hex for Verilog""" q15 = np.round(coeffs * Q_SCALE).astype(int) q15 = np.clip(q15, -32768, 32767) # Clamp to 16-bit signed range return [f"16'sh{v & 0xFFFF:04X}" for v in q15] # ── BASS: low-pass, cutoff 300 Hz ────────────────────────── bass_coeffs = firwin(N_TAPS, 300 / (FS/2), window='hamming') # ── MID: band-pass, passband 300 Hz – 3 kHz ──────────────── mid_coeffs = firwin(N_TAPS, [300/24000, 3000/24000], window='hamming', pass_zero=False) # ── TREBLE: high-pass, cutoff 3 kHz ──────────────────────── treble_coeffs = firwin(N_TAPS, 3000 / (FS/2), window='hamming', pass_zero=False) # ── Print as Verilog localparam arrays ───────────────────── for name, coeffs in [('BASS', bass_coeffs), ('MID', mid_coeffs), ('TREBLE', treble_coeffs)]: hexvals = to_q15_hex(coeffs) print(f"\n// {name} band FIR coefficients ({N_TAPS} taps, Q1.15)") print(f"localparam signed [15:0] COEFF [0:{N_TAPS-1}] = '{{") rows = [' ' + ', '.join(hexvals[i:i+4]) for i in range(0, N_TAPS, 4)] print(',\n'.join(rows) + '\n};') # ── Verify: plot frequency responses (optional) ───────────── import matplotlib.pyplot as plt fig, ax = plt.subplots() for name, coeffs in [('Bass', bass_coeffs), ('Mid', mid_coeffs), ('Treble', treble_coeffs)]: w, h = freqz(coeffs, fs=FS, worN=2048) ax.plot(w, 20*np.log10(np.abs(h)+1e-10), label=name) ax.set(xlabel='Frequency (Hz)', ylabel='Gain (dB)', xscale='log', ylim=[-60,5]) ax.legend(); ax.grid(True); plt.show()
Workflow: Run this script → copy the 3 printed localparam COEFF arrays → paste into fir_filter_bass.v, fir_filter_mid.v, fir_filter_treble.v. The plot will show you the 3 frequency responses — verify they add up to a flat response at unity gain before synthesising.

Common Mistakes & How to Fix Them
No audio outputCheck Phase 1 first — does a pure loopback work? If not, your I2S clocking or pin assignments are wrong. Use Vivado ILA (logic analyser) to probe BCLK and LRCLK on the FPGA pins.
Distorted / clicky audioAlmost always an overflow in the fixed-point arithmetic. Check that the accumulator in the FIR is wide enough. Also check the truncation bit positions when converting back to 24-bit output.
Timing failure in VivadoFIR accumulation across 32 taps in one cycle is too slow for 100 MHz. Pipeline the MAC: register the accumulator after every 4 adds. Or increase the clock period constraint slightly (e.g. 12 ns = 83 MHz).
Simulation works, board failsMissing 2-flop synchroniser on I2S inputs. Metastability causes intermittent bit errors on real hardware that simulation never sees. Add the synchroniser registers.
Wrong frequency responseCoefficients wrong. Re-run the Python script and plot the frequency response. Verify the cutoff frequencies are what you expect before loading to FPGA.
